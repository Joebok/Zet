# Simplify pipeline guards, validation, and polling
Status: complete
Related specification: Docs-Joe/Pipeline Guards Reimagined.md

## Goal
New image asks use current masters and eligible references without an extra recompilation step. Completed images remain reviewable and protected; source differences are advisory. Reduce idle polling while retaining queue ownership, attempt fencing, and harvest integrity.

## Current behavior and boundaries
The five character pipelines use `LocalTemplateRevisionService`, `render_slot_service`, scoped projections, and mode-aware selection. Staged batches require accepted prompt review; `recompile` remains a user option. Final locks verify frozen references and output hashes. Restart and Draft cleanup can clear locks after broad confirmation. Narrative polls target detail every two seconds; Minor polls only during active work. Approved fast coverage is S1–S4 in `tests/e2e/fast.spec.mjs`; the live check is separately requested.

## Work packets
1. Master acceptance: revision service and template controller; commit accepted edits to masters with recovery and conflict checks. Validate isolated no-change/change/conflict cases.
2. New ask preparation: render slots, operation/progression/costume services and character UI; compile current masters/references, remove Recompile and mandatory review. Validate prepared fixtures for all five pipelines.
3. Lock retention: mode selection, asset store, Inventory publication; preserve exact prompt and current selected bytes. Validate Draft/Final and recovery.
4. Completed-image guards: legacy Body/Head/Assembly/Dressing paths; remove source-drift blockers and downstream deselection. Validate source-change cases.
5. FYI markers: character and Narrative records/UI; persist sticky, cheap source-change observations, skipping other candidates behind a lock. Validate persistence and reversion.
6. Protected bulk actions: character, Minor, Narrative services/UI; exact effect preview, in-page individual approval and Approve all, state recheck. Validate cancel, partial, bulk and changed-state cases.
7. Character polling: projections and page controllers; active-work-only compact refresh, one settlement detail. Validate isolated request counts and page state.
8. Minor and Narrative alignment: active-work polling, prompt provenance, protected dialogs and FYI. Validate isolated browser journeys and S1/S3.
9. Integration: update affected Docs, ADR and code map; run `npm run test:e2e`, syntax checks, `git diff --check`; review diff and archive plan only when all packets are complete.

## Constraints and progress
No permanent tests, dependencies, live AI checks, or production-library writes without separate approval. Existing queued asks and retries remain frozen. Same-batch selected references are mode-matched; cross-pipeline references require the same-mode lock, except explicitly configured source-batch behavior.

Implemented: accepted corrections save governing masters with a pending-acceptance recovery marker; new asks compile current masters and same-mode sources while retries keep frozen inputs. Draft/Final and legacy lock paths retain current selected bytes and candidate prompt. Historical lineage publication and FRONT-change clearing were removed. Character, Minor, and Narrative candidates gain permanent advisory source-change markers when a saved difference is observed. Restart, Draft cleanup, Minor deletion, and character batch deletion use server-bound protected-effect previews with per-effect approval and fresh conflict previews. Character view polling reads a compact summary during active work and one detail on settlement; idle character, Narrative, overview, Batches, and closed Activity reads stop.
