## How to judge the first results

Check these as separate properties, so a good likeness does not conceal a failed rotation:

1. **View:** clear three-quarter depth, correct nose direction, level head and a narrower far cheek. An unchanged frontal face or a profile does not pass.
2. **Identity:** same face, eye proportions, coloring and bob as Slot 6, allowing for perspective and hair coverage.
3. **Hair:** part and fringe remain on their anatomical sides. On the right-side view, an eye hidden by the fringe is acceptable. A conveniently exposed eye created by moving, shortening or thinning the fringe is a failure.
4. **Ears:** exactly two attached ears. The far tip is visible on the specified side, smaller/less exposed than the near ear, with its root occluded. Reject extra ears, a detached triangle, stretched ears, or a far ear turned toward the viewer to display its inner bowl.
5. **Framing/style:** complete hair and ear tips, consistent rendering and background.

The visible far tip is a requested result, not a proven consequence of this head's geometry. If it only appears when the ear grows or moves, record that conflict instead of accepting a distorted head. A slightly shallower three-quarter angle can be tried separately, but must be recorded as an angle change.

Start with one result per side. Record the prompt revision, reference, output slot, seed if available, and which checks passed or failed. If a result is promising, repeat it with another seed before treating the prompt as reliable. For a wording comparison, keep the same reference and settings and reuse a seed if the generator supports it; that is a useful comparison, not a guarantee of determinism.

### If a result fails

- **Under-rotation or frontal image copied:** change only the opening operation to a camera instruction: `Move the viewpoint around the same stationary head to its anatomical right side by approximately 45 degrees.` For the left-side trial, use: `Move the viewpoint around the same stationary head to its anatomical left side by approximately 45 degrees.` Keep the rest of that side's prompt unchanged. This alternative remains untested; the initial trial changed viewpoint but did not establish reliable 45-degree rotation.
- **Only the far tip is absent:** first check the angle and existing ear/hair overlap. If the rest is good, a separate edit of that result can test revealing the tip; the instruction must preserve the accepted pose and existing ear size/attachment. Do not hide an anatomy change inside a claimed ear correction.
- **Face shape drifts:** try the contour guidance below as a separate revision. Do not introduce a second image and change the wording in the same comparison.

Edit-first wording is a hypothesis, not an established fix for reference copying or hair occlusion. Qwen's official [edit-prompt guidance](https://github.com/QwenLM/Qwen-Image-2.1/blob/main/prompt_rewrite/prompts/system_prompt_edit.txt) recommends leading with the edit operation and separating changed attributes from preserved content. It does not establish a numerical image-versus-text weighting or guarantee this rotation task.

* Joe accepted all four front-quarter results and all four profile results. Front-quarter angles varied, but identity, side-specific hair and the far ear tips were successful. Exact nominal 45-degree rotation was not the acceptance criterion.
* The right profile successfully hides the entire eye and upper face behind the heavy fringe. The lower cheek, nose, lips and chin remain visible. This is a useful example of **correct occlusion**, rather than a defect to repair by exposing an eye.

### Scheduling and reference ownership

The fullness pass needs an accepted BACK, but the current progression creates BACK after rear quarters. Making final rear quarters depend on BACK while BACK depends on those same final quarters would create a cycle. Two bounded approaches are available; neither is implemented here:

1. **Smaller initial integration:** retain the current stage order, select initial rear quarters, create/select BACK, then offer optional rear-quarter hair refinements using that BACK. Keep original and refined candidate identities and ancestry distinct. This enables the tested finishing operation, but does not by itself reproduce FRONT-anchored profile/rear generation.
2. **Full recipe source policy:** introduce a Head-specific policy in which selected FRONT independently anchors front quarters, profiles, initial rear quarters and direct BACK; selected BACK then guides optional rear-quarter refinements. Keep initial generation and finishing passes separate. Update source guards, preview, render preparation and saved recipe/versioning together; do not change the shared predecessor constant globally and unintentionally alter other pipelines.

In either approach, a guide does not own the camera or whole character. Preserve the existing [ordered prompt contract](../zet/services/chatgpt_prompt_contract.py) and reference-preparation path, recording purpose through its existing fields where possible. A saved operation needs its selected edit base, ordered supporting images, intended transfer, exclusions, resolved universe asset identity or frozen source identity, content hashes, prompt/settings and parent attempts. Keep the model's `<image1>` / `<image2>` wording aligned with the actual attachment order. A changed source should produce a new reproducible attempt; Retry should retain the frozen inputs.

Slot numbers and temporary trial scripts are operator conveniences, not durable dependencies. The job IDs, image indices and hashes above identify the actual trial evidence.
