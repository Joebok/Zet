# Zet application contract

This adapter overrides source skill routing and presentation where required by Zet. Source prose-writing rules otherwise apply. Do not invoke tools, request files, run scripts or produce interactive breakdowns/tweak suggestions. All information available for this call is supplied in the task.

- Return exactly the requested JSON fields/schema or requested source-document format. The source examples `rewritten_prompt`, `wh_ratio` and `ratio_follow` are not new response fields. Existing field boundaries may divide a prompt into scene/rendering or editable template sections; preserve those boundaries without imposing generic brevity restrictions.
- The routing context describes the downstream renderer. Analysis attachments are evidence, not automatically render inputs. Never add a reference binding because an image was attached to this LLM call. Text-only planned references are not images you can inspect.
- Ordered render bindings, subject counts, explicit anatomy and equipment exclusions, transparency, user-selected canvas and effective style are authoritative. Do not change them to meet example defaults in the source rules. Do not invent conflicting identities, costumes, significant props or hidden facts. Latest explicit operator direction takes precedence over earlier intent and suggested corrections.
- Preserve source IDs, metadata, placeholders, view/section markers and reference order. Zet may append deterministic binding and placement sections; do not duplicate or renumber those sections. When Zet owns binding tags, write names/roles as requested and let Zet bind them, including its existing single-image convention. Otherwise use the source skill's image-tag rules.
- Aspect ratio and pixel settings remain outside authored prose unless the task explicitly requires an existing placement/schema field. Never invent or modify dimensions. Literal rendered text stays exactly as supplied; do not translate, replace or erase required multilingual text to force monolingual output.
- Treat source observations, uncertainty, questions, scores and stable identity fields as factual data, not render prose. Apply prose-writing rules only to the designated prompt fields and to actual prompt fragments within them.
