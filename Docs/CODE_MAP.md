## Search and impact routine

1. Search the capability's named symbol with `rg -n '<symbol>' zet Scripts tests` to find real consumers; do not assume all entry points go through a facade method.
2. Read the relevant approved E2E scenario and [fixture server](../tests/e2e/server.py) as well as implementation. Fast fixtures isolate their library and replace external model/render responses; they do not prove live-service correctness. Obtain explicit approval before adding scenarios.
3. For serialization changes inspect both producer and consumer plus [DATA_MODEL](DATA_MODEL.md). For async changes inspect the owning workflow and queue contract.
4. Former scene experiment tools are preserved in [the offline archive](../Archive/scene-builder/README.md). They are not runtime workflows or maintained validation commands.

  `_bind_reference_names` binds first mentions only. `narrative.js` owns Old/New selection UI,

  synthesis. Additional field-action/indicator checks are disposable, not permanent scenarios.

## Fixed render-slot entry points (2026-10-12)
- Character allocation/protection: [render_slot_service.py](../zet/services/render_slot_service.py), called by [local_image_workflow_service.py](../zet/services/local_image_workflow_service.py). The local router exposes view `/slots` generation and `/slots/{slot}/{operation}` actions. Adapter details/summaries use the shared active-candidate merger; Run All Remaining startup recovery reattaches persisted supplemental targets and independent slot collectors. Slot collection uses its own runner lock; ordinary batch runners exclude slot-managed additions.
- Image Generation board and prompt controls: [image_generation_workspace_service.py](../zet/services/image_generation_workspace_service.py), via `/api/image-generation/workspace` detail/import/actions; [ad_hoc_image_generation_service.py](../zet/services/ad_hoc_image_generation_service.py) retains job APIs and child-index result application. The prompt form in `zet.js` can prepend the selected universe's canonical art style.
- Shared controls: [render_slots.js](../zet/web/static/render_slots.js); character live updates in [local_asset_pipeline.js](../zet/web/static/local_asset_pipeline.js), ad hoc board updates in `zet.js`. S2/S3 protect existing publication/Narrative behavior. Separately approved disposable checks verify the reported deep-link, containment, prompt and overlapping-action issues; full Body/Head generation and general recovery remain coverage gaps.

- `image_reconstruction_contract.py` owns frozen v2 target intent/precedence and report validation; `image_true_up_service.py` owns intent-aware comparison and direct composition of selected suggestions/custom feedback. `image_reconstruction_service.py` exposes shared prepare/analyze/revise/render-spec/compare operations independently of board allocation, plus Image Generation wrappers.

- See [ADR 0014](DECISIONS/0014-minor-character-workspaces.md), [data model](DATA_MODEL.md) and [local characters](COMPONENTS/LOCAL_CHARACTERS.md). Maintained S1-S3 remain regression checks; disposable feature journeys use isolated prepared responses.

Minor Character prompt-iteration boards and paired full-size review live in `minor_characters.js`, using the shared `render_slots.js` count control. `MinorCharacterService.iteration_slots` owns four-slot allocation, clear/regenerate and frozen-payload replay; `minor_character_router.py` exposes its slot action endpoint. Review arrows cycle rendered slots within one iteration.

Minor Character slot actions queue independently while renders run; workspace locking serializes allocation/submission without waiting for image completion. Card/review Lock calls accept a candidate ID; the publication service uses candidate-scoped origin keys for repeated same-iteration publication. The editor keeps comparison choice on the left and expanded findings under cards.
