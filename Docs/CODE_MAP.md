# Capability code map

Use this map to select a narrow search, inspect the named entry point and callers, and select approved scenario assertions. Paths and symbols are stable module references; the table is not an exhaustive class inventory. [Components](INDEX.md) explain workflows; [INVARIANTS](INVARIANTS.md) owns contracts.

**Current validation:** [Testing](Testing.md#approved-fast-scenarios) defines S1 (library/Narrative authoring), S2 (front Assembly to Dressing), and S3 (Narrative lifecycle/final assembly), all in [fast.spec.mjs](../tests/e2e/fast.spec.mjs). L is the separately requested [live final-assembly check](../tests/e2e/live.spec.mjs). These are the only maintained scenarios; a mapped scenario covers only its stated assertions, not every contract of a capability. Deleted Python/browser test paths are not runnable checks.

## Search and impact routine

1. Search the capability's named symbol with `rg -n '<symbol>' zet Scripts tests` to find real consumers; do not assume all entry points go through a facade method.
2. Read the relevant approved E2E scenario and [fixture server](../tests/e2e/server.py) as well as implementation. Fast fixtures isolate their library and replace external model/render responses; they do not prove live-service correctness. Obtain explicit approval before adding scenarios.
3. For serialization changes inspect both producer and consumer plus [DATA_MODEL](DATA_MODEL.md). For async changes inspect the owning workflow and queue contract.
4. Experimental comparison/review tooling lives in [scene_assembly_experiment_service.py](../zet/services/scene_assembly_experiment_service.py), [scene_layer_integration_followup.py](../zet/services/scene_layer_integration_followup.py), and related `zet/scripts/scene_*` modules. It has no dedicated maintained scenario and is distinct from Narrative assembly. Inspect authoritative source; new coverage still needs explicit approval.
