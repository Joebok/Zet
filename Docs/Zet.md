# Zet Pipeline

Zet is a web based Dashboard tool to manage image assets and the processes used to create those images.

Zet is organized around a set of Characters. Each Character will have at least one Phase. Phases are intended to be phases of life such as 'Adult' or 'Youth' but it can be anything. In practical terms, <Character> and <Phase> represent a file system path to a folder where relevant files are stored.

## File Organization

config.toml sets the base paths:

```
[BaseFolders]
BaseCharacterPath = "_Lib/Characters/"
BaseAssetPath = "_Lib/Assets/"
BasePipelinePath = "_Lib/Pipelines/"
BaseAIQueuePath = "_Lib/AI_Queue"
```

* The **CharacterPath** is the BaseCharacterPath + /<Character>/<Phase>
* The **CharacterAssetPath** is the BaseAssetPath + /<Character>/<Phase>
* The **PipelinePath** is the BasePipelinePath + /<Character>/<Phase>/<ImageType>/<View>/<HeadFacing> (if set)

All of these paths are programatically determined by the fields indicated.

## Characters

A Character in a Phase has a set of Specifications and Assets.

Specifications are a collection of MarkDown files in the **CharacterPath**.

A list of Assets and their States and other properties is kept in the CharacterPath: Assets.json
A list of Pipelines and their state and other properties is kept in the CharacterPath: Pipelines.json

Asset represent images files in the **CharacterAssetPath** which were generated by executing a Pipeline and after review, being promoted to "LOCKED" by the Dashboard.

Intermediate files used in the production of assets are stored in the **PipelinePath** related to specific Pipelines. 

Python scripts inspect and read and store files in all of these folders.

## Asset Overview

An Asset is a record that represents an image. The image is a specific <ImageType> of a <Character> in a <Phase> from a specified <View>. Optionally a <HeadFacing> may be specified. (<HeadFacing> is left blank by default). An image for an asset is created by following an <Pipeline> determined by the Asset <ImageType>

The images a completed set of Assets for a given <ImageType> is a 'Turnaround Set' for that <ImageType> - a series of images showing the character from 8 different viewpoints.

Each Asset has several state fields:

* AssetState: indicates if the Pipeline hasn't been started, is in progress, is finished, or if it is blocked and requires an Agent to investigate.

* PipelineStage: indicates the fine detail of the image generation process which is generally staging required resources, Prompt generation, optional Prompt Review, Image Rendering, optional Image Review, and finally finished. At that point the AssetState is updated to "LOCK_REVIEW" and waits on a Human agent to review.

## Python Scripts

Python scripts will be used to govern the progression of PipelineStages in an Asset. Generally AssetState will be controlled by humans operating the Dashboard. Such AssetStage. changes will likely invoke Pipeline State-Change scripts.

Most scripts will govern Piplelines and will fall into one of the categories listed below. Each such script will be passed the Asset it is to operate on plus any additional parameters as needed (particularly error indicators).

### Polling 

Scans the Asset table looking for specific conditions to take action. Can be invoked manually from the Dashboard. Every Pipeline will have it's own Polling Script. Polling Scripts call Worker scripts.

### Worker

Performs the work required for the Asset and PipelineStage. When done, it will call the appropriate State-Change script. Worker scripts will also pass on error indicators for the State-Change scripts to process.

Every Pipeline and PipelineStage will likely have a dedicated Worker-Script.

### State-Change
 
State-Change scripts validate the work done by a Worker script and then updates the PipelineStage stage accordingly (either advance it and set the Actor or revert it to ERROR). State-Change scripts are called by Worker scripts and also by functionality impemented in the Dashboard. State-Change scripts call House-Keeping scripts after the PipelineState has been updated.

### House-Keeping

Prepares the PipelinePath for the assigned PipelineStage. It is invoked after a State-Change script has changed the PipelineStage. 

### AI-Handler

For PipelineStages where the Actor is "AI_Agent", an AI-Handler script manages the AI_State field of the Asset which involves preparing the PipelinePath, generating a script, queueing the Asset to the AI_Manager, then processing AI_State changes that the AI_Manager invokes when it receives results. The AI-Handler will then call the appropriate State-Change script.

### Batch

Sometimes an action requires the update of more than one Asset. A Batch script will iterate through all the Assets and call the appropriate State-Change or other type of script as necessary.

## PipelineStage Details

An Asset is of a <Pipeline> for a designated <Character> and <Phase>. Each Asset also specifies view angles and head orientation that will be used by Worker scripts to do their jobs. The Asset record is used to determine file and path information for resources necessary to complete the work (the PipelinePath). 

A Pipeline is one of:

* Body-Reference
* Head-Fitment
* Character-Assembly

Future ImageTypes yet to be documented are:

* Costume-Fitment
* Expression

Each Asset has a **PipelineStage** which is governed by State-Change scripts.

A PipelineStage is one of:

* MANIFEST
* PROMPT
* PROMPT_REVIEW
* RENDER
* GPT_HANDOFF
* RENDER_REVIEW
* ERROR

The PipelineStages will generally progress:

MANIFEST -> PROMPT -> (Optional) PROMPT_REVIEW -> RENDER -> (Optional) GPT_HANDOFF -> RENDER_REVIEW

With each state change governed by State-Change scripts to validate and either move to the next PipelineStage or set to ERROR state.

Each PipelineStage also has an **Actor**. Which Actor is associated with with PipelineStage is configurable with a lookup to a .json table in the CharacterFolder. When a State-Change script runs, it will set the Actor accordingly.

An Actor is one of:
* PYTHON
* AI_AGENT
* HUMAN_AGENT

If the Actor is PYTHON, the job will be queued for processing by a Polling script.

If the Actor is HUMAN_AGENT, a human will need to perform an action on the Dashboard. This could be reviewing an image or investigating an error. The human will indicate either **Pass** in which case a Python state chage script will advance the Pipeline or **Fail** in which case the human designates which PipelineStage to revert to. A State-Change scripts set the new PipelineStage, call Housekeeping, etc. 

If the Actor is AI_AGENT, then a python AI-Hander script will construct the prompt for the job and queue up for processing. These jobs are run asyncronously and so an **AI_State** field is used to indicate the status of the request:

An AI_State is one of

* ASKED
* WAITING
* ANSWERED

An AI_Manager handles interacting with AI models by managing the AI_State. An AI-Handler will set the AI_State to ASKED, the AI_Manager will prepare prompts and resorces, send to an AI Model, setting the AI_State to WAITING. The AI_Manager polls for returned answers and when found, sets the AI_State to ANSWERED and invokes the appropriate Change-State script.

## Asset Fields

### Key Fields
 - validates the work done by a Worker script, updates the PipelineStage, calls House-Keeping.

Every Asset tracks an image that is identified by:
* <Character>
* <Phase>
* <BodyView>
* <HeadView>
* <Pipeline>
* <Costume>
* <Expression>

Together, these form a unique key. If it is easier for processing, an <AssetID> can be added to store an easier managed reference.

### State Fields

Every Asset has a set of State fields govered by State-Change scripts for management:

* <AssetState>
* <PipelineStage>
* <AI_State>

Descriptions of allowed states are above.

### Additional fields for pipeling processing

* <Final_Image_Output> - the filename that the asset will have in the file system.
* <Last_AI_Update> - a string containing date/time and a message. For example "6/27/26 - Waiting for 45 minutes..." The AI_Manager is responsible for putting messages here for the Dashboard.

## The Dashboard

A StreamLit site will show the Asset list with certain defined view on different tabs to fascilitate human work. The dashboard works only with one Character/Phase at a time. A list of Characters and Phases should be drawn from the file system, looking at all the possible CharacterPaths and constructing Character and Phase drop-down boxes. These boxes should be at the top of the screen, next to each other.

### Main Tab

Shows the Asset List, all non-character and non-phase key fields and all state fields for the asset.

Selecting a row should show the image(s) associated with that Asset. If there is an image of the Final_Image_Output name in the PipelineFolder, show it under the table on the left under the caption "Candidate". If there is an image of the Final_Image_Output name in the CharacterAssetPath, then show that image on the right under the caption "Locked".

If there is a candidate image, there should be buttons for
* Promote to LOCKED
* Regenerate

Both of these will invoke AssetState State-Change scripts.

## Pipeline Tab

A drop-down box of all Pipeline types should be at the top. Its selection determines the Asset rows to show. Also on the same line as the dropdown, a "Regenerate" button that will invoke a Batch script to run PipelineStage State-Change scripts to set all to "MANIFEST"

Next to that a "Poll Pipelings" button that will invoke the Pole script for that Pipeline.

Under, show a table with

Fields are Pipeline, PipelineStage, Actor, AI_State

Highlight rows that need human action (Actor=Human)

When a row is clicked, show the full detail of the asset record (except for Character, Phase, and Pipeline). If in the PipelinePath there are PromptFiles (Promt_*.md) show them at the top with clickable links that will show the contents of the file.

## AI Manager Tab

Show assets where Actor = AI_Agent. Show Pipeline, PipelineStage AI_State and Last_AI_Update.

A clicked row shows full detail, just like on the Pipeline tab. A "Retry" button should be presented (above the full detail) which will set the call the AI_State manager to set the AI_State to "ASKED"
